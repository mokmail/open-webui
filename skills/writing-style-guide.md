# Writing Style Guide

## Tone & Voice

- Write in a clear, confident, and professional tone.
- Use active voice unless passive genuinely improves clarity.
- Address the reader directly using "you" when giving instructions.
- Be concise: prefer short sentences and simple words. Avoid jargon unless the audience expects it.
- Avoid hedge words: "might", "maybe", "possibly", "sort of". State things directly.
- Use consistent terminology throughout. Pick one term for a concept and stick with it.

## Formatting Rules

### Headings
- Use sentence case for headings (capitalize only the first word and proper nouns).
- Use a single H1 per document. Nest headings logically (H1 → H2 → H3).
- Every heading must be followed by content — avoid orphan headings.

### Lists
- Use numbered lists for sequential steps or ranked items.
- Use bullet lists for non-ordered items.
- Keep list items parallel in structure (all nouns, all verbs, etc.).
- Capitalize the first word of each list item. End with a period only if the item is a full sentence.

### Code
- Inline code: use backticks for commands, filenames, variables, and short code snippets.
- Code blocks: use fenced blocks with a language identifier for any multi-line code.
- Format code consistently — prefer the project's formatter output.

### Links & References
- Use descriptive link text (not "click here" or "link").
- For external references, include the full URL in a footnote or visible link.

## Document Structure

1. **Title** — Clear, descriptive, one line
2. **Context** — 1-3 sentences explaining what this document covers and who it's for
3. **Body** — Organized with logical headings, examples, and explanations
4. **Summary** — Optional: recap key takeaways at the end

## What to Avoid

- Emojis in professional or technical documentation unless the brand calls for them
- Exclamation marks in technical instructions
- Assumptions about reader's prior knowledge — link to prerequisites instead
- Overuse of bold and italic formatting — use them sparingly for emphasis only
- Ambiguous pronouns ("it", "this") without clear antecedents
